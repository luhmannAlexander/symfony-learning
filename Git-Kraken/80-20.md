# GitKraken in 20 Stunden lernen

## So nutzt du den Plan

Jeder Block dauert 2 Stunden: etwa 105 Minuten Lernen und Anwenden, danach 15 Minuten Überprüfung. Arbeite möglichst mit einem eigenen Übungs-Repository und führe die Schritte selbst in GitKraken aus. Die Menübezeichnungen können je nach GitKraken-Version leicht abweichen.

## Block 1 – Orientierung und erstes Repository

**Was gelernt werden soll**

- Oberfläche verstehen: Graph, Local Repositories, Commit-Liste, Branches und Arbeitsbereich.
- Ein bestehendes Repository öffnen oder klonen.
- Änderungen und den Status eines Repositories erkennen.
- Den Unterschied zwischen Git (Versionsverwaltung) und GitKraken (grafische Oberfläche) verstehen.

**Lernressource**

- [GitKraken Docs: Getting Started](https://help.gitkraken.com/gitkraken-client/getting-started/)

**15-minütige Überprüfung**

Klon ein kleines öffentliches Repository, finde den neuesten Commit, öffne den Commit-Detailbereich und erkläre dir laut, was die farbigen Linien im Graph bedeuten.

## Block 2 – Änderungen, Staging und Commits

**Was gelernt werden soll**

- Dateien ändern, neue Dateien anlegen und gelöschte Dateien erkennen.
- Änderungen im Diff lesen.
- Ausgewählte Änderungen stagen und einen aussagekräftigen Commit erstellen.
- Gute Commit-Nachrichten schreiben: kurz, konkret und im Imperativ.

**Lernressource**

- [GitKraken Docs: Commit Changes](https://help.gitkraken.com/gitkraken-client/commit-changes/)

**15-minütige Überprüfung**

Erstelle drei kleine Änderungen, stage jeweils nur die passende Datei bzw. den passenden Teil und committe sie getrennt. Zeige anschließend im Graph, welcher Commit welche Änderung enthält.

## Block 3 – Branches und Navigation

**Was gelernt werden soll**

- Warum Branches parallele Arbeitslinien sind.
- Branch erstellen, umbenennen, wechseln und löschen.
- Zwischen Commits navigieren und einen Branch aus einem bestimmten Commit erzeugen.
- HEAD und den aktuellen Branch im Graph einordnen.

**Lernressource**

- [GitKraken Docs: Branches](https://help.gitkraken.com/gitkraken-client/branching/)

**15-minütige Überprüfung**

Erstelle `feature/suche`, committe dort eine Änderung und wechsle zurück zu `main`. Beweise, dass die Änderung auf `main` noch nicht sichtbar ist, und lösche den Test-Branch danach.

## Block 4 – Remote-Repositories und Synchronisieren

**Was gelernt werden soll**

- `origin`, Remote-Branch sowie lokale und entfernte Historie unterscheiden.
- Fetch, Pull und Push sicher verwenden.
- Ein Repository mit GitHub, GitLab oder Bitbucket verbinden.
- Vor dem Push prüfen, was tatsächlich veröffentlicht wird.

**Lernressource**

- [GitKraken Docs: Push and Pull](https://help.gitkraken.com/gitkraken-client/push-pull/)

**15-minütige Überprüfung**

Push einen neuen Branch zu einem eigenen Remote-Repository, ändere die Datei zusätzlich über die Weboberfläche, hole die Änderung mit Fetch/Pull ab und beschreibe den Unterschied zwischen beiden Schritten.

## Block 5 – Merge und Konflikte

**Was gelernt werden soll**

- Einen Feature-Branch in den Ziel-Branch mergen.
- Fast-forward- und Merge-Commit im Graph erkennen.
- Einen einfachen Konflikt im integrierten Editor lösen.
- Konfliktdateien prüfen, als gelöst markieren und den Merge abschließen.

**Lernressource**

- [GitKraken Docs: Merge Conflicts](https://help.gitkraken.com/gitkraken-client/merge-conflicts/)

**15-minütige Überprüfung**

Erzeuge absichtlich einen Konflikt, indem du dieselbe Zeile auf zwei Branches änderst. Löse ihn bewusst, committe die Lösung und erkläre, welche Version du behalten hast und warum.

## Block 6 – Rebase, Undo und sichere Korrekturen

**Was gelernt werden soll**

- Merge und Rebase anhand des Graphs vergleichen.
- Einen privaten Feature-Branch interaktiv rebasen und Commits neu anordnen oder zusammenfassen.
- Änderungen verwerfen, einen Commit zurücknehmen und einen Branch auf einen früheren Stand setzen.
- Verstehen, warum man bereits geteilte Commits nicht leichtfertig umschreibt.

**Lernressource**

- [GitKraken Docs: Rebase](https://help.gitkraken.com/gitkraken-client/rebase/)

**15-minütige Überprüfung**

Erstelle zwei Test-Commits, fasse sie per Interactive Rebase zusammen und nutze danach Revert für einen weiteren Commit. Prüfe, dass die Historie verständlich bleibt und die Datei den gewünschten Inhalt hat.

## Block 7 – Stash und sauberes Arbeiten

**Was gelernt werden soll**

- Unfertige Änderungen mit Stash parken und wiederherstellen.
- Zwischen Aufgaben wechseln, ohne unfertige Arbeit zu committen.
- Stashes ansehen, benennen, anwenden und löschen.
- Kleine, thematisch zusammengehörige Commits als Arbeitsroutine nutzen.

**Lernressource**

- [GitKraken Docs: Stash](https://help.gitkraken.com/gitkraken-client/stash/)

**15-minütige Überprüfung**

Beginne eine Änderung, stash sie, wechsle auf einen anderen Branch, committe dort eine dringende Korrektur und stelle anschließend den Stash wieder her. Prüfe beide Änderungen getrennt.

## Block 8 – Pull Requests und Code-Review

**Was gelernt werden soll**

- Einen Pull Request aus GitKraken heraus erstellen.
- Basis-Branch, Ziel-Branch, Titel und Beschreibung sinnvoll wählen.
- Review-Kommentare lesen, beantworten und Änderungen nachliefern.
- Statuschecks und Merge-Voraussetzungen verstehen.

**Lernressource**

- [GitKraken Docs: Pull Requests](https://help.gitkraken.com/gitkraken-client/pull-requests/)

**15-minütige Überprüfung**

Erstelle in einem eigenen Repository einen Pull Request mit einer kurzen Beschreibung und einem Testhinweis. Führe eine simulierte Review durch, behebe einen Kommentar und pushe die Nachbesserung.

## Block 9 – Team-Workflow und tägliche Praxis

**Was gelernt werden soll**

- Einen einfachen Team-Workflow beherrschen: aktualisieren, Branch erstellen, committen, pushen, Pull Request, reviewen, mergen.
- Branch-Namen und Commit-Nachrichten konsistent verwenden.
- Veraltete Branches erkennen und nach dem Merge aufräumen.
- Commit-Suche, Fuzzy Finder und integrierten Terminal gezielt nutzen.

**Lernressource**

- [Atlassian Git Tutorial: Git Workflows](https://www.atlassian.com/git/tutorials/comparing-workflows)

**15-minütige Überprüfung**

Simuliere eine komplette Aufgabe von der Branch-Erstellung bis zum gemergten Pull Request. Nutze dabei mindestens einen Review-Zyklus und räume lokale sowie Remote-Branches anschließend auf.

## Block 10 – Abschlussprojekt und Fehlerbehebung

**Was gelernt werden soll**

- Einen realistischen Mini-Workflow ohne Anleitung durchführen.
- Häufige Probleme diagnostizieren: falscher Branch, fehlender Push, Konflikt, abweichende Historie und versehentlich geänderte Datei.
- Vor riskanten Aktionen den Graph prüfen und bei Bedarf einen sicheren Rückweg (Branch oder Tag) anlegen.
- Die wichtigsten GitKraken-Aktionen als persönliche Checkliste festhalten.

**Lernressource**

- [GitKraken Docs: Undoing Changes](https://help.gitkraken.com/gitkraken-client/undoing-changes/)
- [Pro Git: Git Basics](https://git-scm.com/book/en/v2/Git-Basics-Getting-a-Git-Repository)

**15-minütige Überprüfung**

Baue eine kleine Änderung, löse einen absichtlich erzeugten Konflikt, erstelle einen Pull Request und mache danach eine kontrollierte Korrektur per Revert. Bestehe den Abschluss, wenn du jeden Schritt erklären kannst und dein Repository einen sauberen, nachvollziehbaren Graph zeigt.

## Nach den 20 Stunden

Wiederhole den Ablauf aus Block 9 regelmäßig an einem echten, ungefährlichen Projekt. Nutze die Kommandozeile nur ergänzend, wenn GitKraken eine Funktion nicht anbietet oder du die zugrunde liegenden Git-Befehle besser verstehen möchtest.
